Open-source driver for macOS 11 and later

Print to your Xerox WorkCentre 3025 from a current Mac.

Xerox's Mac driver stops at macOS 10.14. This package brings the open-source SpliX encoder to macOS as a native CUPS driver, so the WC3025 works over USB on Apple Silicon and Intel Macs.

Free, GPL-2.0. Printing only; scanning isn't included.

Why this exists

The WorkCentre 3025 doesn't speak PostScript, PCL or AirPrint. It only accepts Samsung's host-rendered format, SPL (QPDL v3), so the Mac has to produce the exact byte stream itself. Generic drivers can't do that, and Xerox never updated its own driver past macOS 10.14.

SpliX, now hosted by OpenPrinting, already encodes QPDL for the WC3025 and its Samsung twin, the M2070 series. This project builds it for current macOS, fixes a few bugs, and packages it as a signed universal filter with a PPD that macOS can pick up.

  • Native CUPS driver, no emulation or print server
  • Universal binary for Apple Silicon and Intel
  • 23 paper sizes, A3 to postcards and envelopes
  • 600 and 1200 DPI
  • Manual 2-sided printing
  • Toner save, toner density, paper type and manual feed
  • Output checked bit for bit in CI before every release

Install

  1. Download and run the installer

    Get the .pkg from the latest release and open it.

    The package isn't notarized by Apple, so macOS may refuse to open it. Go to System Settings → Privacy & Security and click Open Anyway, or install it from Terminal: 

    sudo installer -pkg ~/Downloads/Xerox-WorkCentre-3025-SpliX-<version>.pkg -target /

  2. Connect the printer

    Plug the WorkCentre 3025 into your Mac over USB and turn it on.

  3. Add the printer

    Open System Settings → Printers & Scanners → Add Printer and select the WorkCentre 3025. Under Use, choose Xerox WorkCentre 3025 SpliX. If it isn't preselected, pick it with Select Software…

Add the printer from the command line 
/usr/libexec/cups/backend/usb          # prints the printer's usb:// URI
lpadmin -p WC3025 -E -v 'usb://Xerox/WorkCentre%203025?serial=…' \
  -P "/Library/Printers/PPDs/Contents/Resources/Xerox WorkCentre 3025 SpliX.ppd.gz"
Build from source

Needs the Xcode command line tools. Clone the repository, then:

make test       # optional: offline end-to-end check
make install    # builds the .pkg in build/ and runs the installer (sudo)

From a source checkout, run make uninstall. Without one, remove the files directly: 

sudo rm -rf /Library/Printers/SpliX
sudo rm -f "/Library/Printers/PPDs/Contents/Resources/Xerox WorkCentre 3025 SpliX.ppd.gz"
sudo pkgutil --forget io.github.splix.wc3025

Printer queues aren't deleted. Remove them in Printers & Scanners.

How it works

macOS rasterizes each page itself, halftoning included. The driver only has to compress that raster and wrap it in the printer's language.

  1. Your appprints
  2. PDFmacOS print system
  3. cgpdftorasterApple filter
  4. CUPS raster1-bit, 600/1200 DPI
  5. rastertoqpdlthis driver
  6. PJL + QPDL v3printer job
  7. USBWorkCentre 3025

Banded compression

rastertoqpdl slices each page into 128-row bands, compresses them with Samsung's algorithm 0x11, and adds a checksum to each band.

Model parameters in the PPD

The PPD carries what SpliX needs to know about the WC3025: QPDL v3, 512-byte packets, the M2020 band-width table and manual duplex.

Fits macOS security

/usr/libexec/cups is protected by SIP, so the filter lives under /Library/Printers and the PPD points to it by full path.

Tested without a printer

Every push and every release runs the real macOS print pipeline offline on GitHub Actions, for A4 and Letter at 600 and 1200 DPI.

This proves the job is well-formed and carries the right image. Only a real print proves the printer accepts it.

  1. cupsfilter turns a generated 2-page PDF into CUPS raster with Apple's filters and this PPD.
  2. The built rastertoqpdl turns that raster into a printer job.
  3. A Python QPDL decoder checks PJL framing, page and band headers and every band checksum.
  4. Every band is decompressed and compared bit for bit with the input raster.
  5. The chain runs again through the PPD's own filter line and must produce identical pages.
  6. A job title with quotes and an embedded @PJL line must not break the job header.

Your first test print

  1. Print both pages of the test page: A4 (PDF) · Letter (PDF)
  2. The frame shows on all four sides.
  3. The diagonals are continuous, with no seam every 128 rows.
  4. The gray ramp shows distinct steps, and page 2 follows page 1.
  5. Print it again at 1200 DPI, set under Printer Features in the print dialog.

About 2-sided printing

The WC3025 has no duplex unit, so 2-sided jobs are manual. The printer prints one side, then asks you to put the stack back in the manual tray for the other side.

If something goes wrong

Collect the printer's device ID and a CUPS debug log, then open an issue with both attached.

Driver not preselected? The PPD's device ID (MFG:Xerox;MDL:WorkCentre 3025;) is a best guess. If your printer reports a different MDL:, choose the driver by hand. Printing works either way, and the issue helps fix the guess. 

/usr/libexec/cups/backend/usb    # the printer's IEEE-1284 device ID
cupsctl --debug-logging          # then print again
log show --last 10m \
  --predicate 'process == "cupsd" OR process CONTAINS "rastertoqpdl"' \
  > cups.log
cupsctl --no-debug-logging

Changes to upstream SpliX

The repository's first commit is a pristine copy of OpenPrinting/splix@7a80218, so git diff against it shows every change.

src/semaphore.cpp
Always signal on post. Upstream only signalled on the 0→1 transition, which can lose wake-ups when several threads wait.
src/cache.cpp
whatToDo = ~whatToDo on a bool is always true, so the cache thread never alternated between preloading and storing. Now uses !.
src/printer.cpp
Job titles and user names are sanitized before going into quoted PJL strings: " becomes ', control characters become spaces, and values are cut at 79 bytes.
src/document.cpp
Reads raster headers with the current CUPS API (cupsRasterReadHeader2) and detects monochrome pages from cupsNumColors.

Built without JBIG, since the WC3025 uses algorithm 0x11. pstoqpdl isn't built, because macOS rasterizes PDF itself.
